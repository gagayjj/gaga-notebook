## 一、免费 AI 通道：为什么老是返回空

**现象**：推荐 10 部剧，免费通道连续几次返回空内容。

**根因（做实验钉死的）**：免费通道是 Pollinations 的 `gpt-oss-20b`，**推理模型**。匿名额度约 1500 completion tokens，默认思考量把额度全烧在 reasoning 上 → 返回 `finish_reason:length`、content 是空的。跟 UA、代理、Electron 都没关系（用 Electron 内 fetch 探针 + 对比 node/curl 排除了所有假设才定位到）。

**修法**：请求体加 `reasoning_effort:"low"`。改完 6~10 秒稳定出内容（10 部剧 JSON 只花 345 tokens）。

配套三处：
1. `src/aiTutor.ts`：`callAiTutor` / `askAiFree` 免费分支都带这个参数。
2. `electron/main.cjs`：`ai:tutor` 透传参数；**402/429/5xx 也纳入重试**（匿名限流很凶，连点两下第二个请求必 402），退避 3s/10s/20s/30s。
3. `JuyouciPanel.tsx`：免费模型输出的 JSON 经常**漏写 `{`**（第 2 条起变成 `"name":...`），严格 `JSON.parse` 必挂 → `parseShowsText` 用正则逐条兜底。

## 三、追剧精听：从「点了没反应」到能学

**需求**：选定一部剧后，要像 TED 精听那样视频 + 字幕逐句同步。

**版权边界（这条定死了）**：剧集正片不能内置。做成**用户自备本地视频 + .srt/.vtt 字幕**；纯文本台词（没有时间轴）降级成"点一句读一句"的台词模式。

做了什么（`JuyouciPanel.tsx`，class 前缀 `jy-binge-*`，不复用 `ted-*` 以免干扰 QA 选择器）：
- 视频：桌面端 `openVideoDialog()` + `localVideoUrl(path)`（路径存 `juyouci-show-video`，重启还在）；网页端 file input + blob URL（每次重选）。
- 字幕：`parseSubtitles` 解析 SRT/VTT 时间轴，原文存 `juyouci-show-srt`。
- TED 同款：当前句大字、逐句列表高亮同步、点句子跳转、⏮▶⏭、进度条、倍速、单句循环；朗读用有道 dictvoice（正常/慢速）；「译」走 AI；点任意单词弹查词卡 → 一键加生词本。
- 「有反应」：`pickShow` 现在自动展开精听区并滚过去。

## 四、"两边不同步"：逐句停顿

**澄清一个误解**：TED/追剧精听里只有视频自带那一轨声音，字幕高亮完全由视频时间驱动，**没有第二套朗读在抢拍**。

用户感知的"语音没说完文字就换句"，是连续播放时一到下一句起始时间就立刻切走（说话人尾音/停顿落在下一句的时间窗里）。

**修法**：加「逐句停顿」模式（`tedSentencePause` / `bingeSentencePause`，都持久化）。句末自动 pause，字幕钉在当前句；点「继续」= 前进到下一句开头再播（避免原地死循环）。

## 七、内置免费视频库：12 → 35 篇

这是「App 自动给视频」唯一合法的路子。

**机制**：`scripts/fetch-ted.mjs` 抓 ted.com 官方页的 `__NEXT_DATA__` → 取 `py.tedcdn.com/...mp4` 直链 + 时间轴字幕 → 写 `public/ted/*.json`（vite 打包进 `dist/ted/`）。桌面走 IPC `ted:list`/`ted:get`，网页端 `fetch("ted/index.json")` 兜底。

**扩库方法**：往 `TALKS` 数组加 slug 再跑脚本。**脚本自带验证——404 / 无字幕的会自动跳过，不会写进清单**（杜绝编造）。这次加了 26 条候选，3 条 404 被跳过，12 篇变 35 篇，里面还有 3~7 分钟的短篇当"教学切片"。

**TED-Ed 走不通**：ed.ted.com 页面只有 YouTube embed ID，没有直链 mp4，也没有字幕数据 → 做不了逐句精听。放弃了，没造假。

**跳转入口**：`JuyouciPanel` 加 `onOpenLibrary` prop，父组件传 `() => setTab("ted")`；追剧精听页没视频时显示「不想等？用内置免费视频练」。

**美剧三步引导**（`.jy-binge-guide`）：① 返回剧单点「在哪能找到」 ② 视频和 .srt 下到同一文件夹 ③ 点按钮选文件。

## 八、B站 / 抖音能不能取视频（实测，不是猜）

| 环节 | B站 | 抖音 |
| --- | --- | --- |
| 拿视频详情 | ✅ | — |
| **下载播放流** | ✅ 480p mp4，实测下到 4.9MB | ❌ |
| **拿带时间轴的字幕** | ❌ **字幕条数 = 0** | ❌ |
| 按博主 ID 列视频 | ❌ `-352 风控`（要 wbi 签名/登录） | ❌ |

抖音搜索页返回 200、72KB，但关键词「福安」出现 **0 次**，也没有 `__INITIAL_STATE__` / `aweme_list`——空壳，要登录态 + 动态签名。用户接口直接回 `url doesn't match`。

**结论：视频能下、字幕拿不到 → 没有时间轴就做不了逐句高亮/跳转/跟读/查词，最后只是个普通播放器。**

**立场（已跟用户讲明）**：不把"批量抓 B站/抖音"做成软件功能（平台禁止抓取 + 规模化下载侵权内容）；但可以处理用户本地已有的视频文件。

B站接口要先拿设备指纹 cookie 才能用：
`GET https://api.bilibili.com/x/frontend/finger/spi` → 取 `b_3` → 请求带 `buvid3=...` + `Referer: https://www.bilibili.com/`。

## 九、还没做的：自动生成字幕（ASR）

这是绕开"拿不到字幕"的唯一办法：**用户本地视频 → ffmpeg 抽音轨 → macOS 系统语音识别（SFSpeechRecognizer）→ 逐句字幕（带 timestamp/duration）→ 进逐句精听**。这样她不用再到处找 .srt，从抖音/B站 保存到本地的视频都能用。

已备好的东西：
- `/tmp/asr_test.swift`：SFSpeechRecognizer，输出 `[{text, t, d}]` JSON，并打印授权状态。
- `/tmp/t20.wav`：用 `say -v Samantha` 合成的英文测试音频（201KB）。
- 本机 ffmpeg 在 `/usr/local/bin/ffmpeg`（不在 PATH，要写全路径）。

**最大风险**：swift CLI 没有 Info.plist，`requestAuthorization` 可能被 TCC 拒绝（权限按可执行文件身份算）。被拒的话要么给 CLI 补 Info.plist 并签名，要么换 whisper.cpp 这类离线方案。

## 十、复习调度（间隔重复）：从「背了就忘」到按计划复现

**需求背景**：用户要"手机和电脑一样的体验"，生词背完就丢、没有复习节奏。决定做间隔重复（spaced repetition），并随同步走。

**数据模型**（`src/types.ts` 的 `StudyWord`）：加 4 个字段
- `srStatus: "new" | "learning" | "review" | "known"`（掌握度：新 / 学 / 待复习 / 已掌握）
- `srDue: string`（ISO 时间，到期才出现复习）
- `srInterval: number`（当前间隔天数）
- `srReps: number`（连续认识次数）

`Window.studyNotes` 新增 `updateWord(id, patch)`（`src/types.ts:260` 声明，`src/browserAdapter.ts` 实现）。

**算法**（`src/components/EnglishLearning.tsx` 的 `srGradePatch`）：
| 评级 | 间隔变化 | 下次到期 | 状态 |
| --- | --- | --- | --- |
| 认识 | 0→1 天，之后 ×2.5 | +间隔天 | 连对≥5 次或间隔≥16 天 → `known`，否则 `review` |
| 模糊 | 减半（最少 1 天） | +间隔天 | `learning`，连对计数清零 |
| 不会 | 0 | 当天 | `learning`，连对清零 |

`known` 之后不再进「今日复习」（永久免打扰）。

**UI**（`EnglishLearning.tsx`）：单词本顶部加「今日复习」面板，列出所有 `srDue ≤ now` 且非 `known` 的词，每词三个按钮（认识/模糊/不会）；单词项加掌握度小标签（新/学/待复习/已掌握 四色）。样式在 `src/styles.css`（`.review-panel` / `.sr-chip` + 四色）。

**同步贯通**：`src/lib/sync-core.ts` 的 `toBundle` 用 `{...word}` 展开，`mergeLists` 按 `updatedAt` 取最新 → 新增的 4 个复习字段跟着单词一起同步，手机/电脑不丢。已用 grep 确认 `srStatus`/`srDue`/`srInterval`/`srReps` 在 types、browserAdapter、EnglishLearning 三处贯通。

**验证**：`env -u NODE_OPTIONS npx tsc -b` 通过（0 错误）；构建通过；grep 确认 `srGradePatch`/`reviewCustomWord`/`srIsDue` 在 `EnglishLearning.tsx` 实现且被引用（1902/1905/1908/1917-1919 行）。**功能级交互未跑 QA**（Electron 需 `env -u ELECTRON_RUN_AS_NODE` 启动，未在此环境实跑），按规则标"待验证"——下次启动 App 点一下「今日复习」三个按钮确认即可。

## 十一、追剧精听：只说剧名+集数 AI 出词表

**需求（用户原话重述）**：看到《某剧》第几集，告诉 AI（"视频直接发给豆包"），AI 把那集生词收集起来能反复练习；而现在版本要"自己找视频下载再上传才能学"——太麻烦。

- 选「只说剧名+集数」：填剧名（必填）+ 集数（可留空），点「生成词库」→ AI 凭记忆挑 10~12 个（免费）/ 15~20 个（付费）高频实用词。
- 复用 `JyLib` 结构（已有「学习与回忆」翻卡 + 「词汇总览」反复练习），所以"收集起来能反复练习"直接达成，不用新写练习页。

**一个重要设计说明（避免误解）**：这一集的词进的是「剧有词」词库，用的是词库自己的**翻卡反复练习**；它**不会**进单词本（customWords），所以**不吃刚做的复习调度（间隔重复）**。原因：用户要的是"那集词收集起来反复练"，词库翻卡已满足；复习调度是单词本那条线。两条线目前独立。若以后想让"追剧收的词"也进单词本走间隔重复，是单独一步（把 `aiGenerated` 词批量 `addWord` 进 customWords），当时没做、没问——按需再说。

## 踩过的坑（照着避）

1. **免费通道必须带 `reasoning_effort:"low"`**，否则推理模型把额度烧光返回空。
2. **免费模型输出的 JSON 会漏 `{`**，解析一律容错（正则逐条提取），别裸 `JSON.parse`。
3. **「整页展开」这类状态存 sessionStorage，别存 localStorage**——存永久会让重启后直进子页面，把主界面藏掉。
4. **桌面 App 开着时 vite 构建会 EPERM unlink dist** → 先 `mv dist dist-old-backup` 再构建（rename 不受打开文件锁影响）。
5. **`executeJavaScript` 注入脚本两个坑**：不能写 TS 语法（`(x as Y)` 直接 SyntaxError）；模板字符串里的 `\n` 会被 Node 先吃掉变成真实换行，要写 `\\n`。
6. **QA 用持久 profile 会互相污染**（上一轮留下的状态让下一轮全挂）；跑关键验证时用全新的 `--user-data-dir`。
7. **模型看不了截图**：聊天里发的图不会落到磁盘。用户把截图存到桌面后，用 `swift scripts/ocr.swift "<图片路径>"` 能 OCR 出中文+英文文字（实测读出 TED 页面结构）。
